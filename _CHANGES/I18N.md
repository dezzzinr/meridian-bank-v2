# Translator — 15 locales, whole-site coverage

Every public page translates completely: switch language and the page you are on changes,
not a subset of it. Arabic flips the layout to RTL.

**Measured coverage: 1,577 / 1,577 translatable strings (100%) across 20 public routes**
(text nodes **and** the visible attributes — placeholders, aria-labels, titles, image alts),
and 14 locales × 20 routes re-tested in a real browser with zero strings left in English
(`npm run i18n:verify`).

## What's in the box

| File | Role |
| --- | --- |
| `src/lib/i18n/locales.ts` | the 15 locales (code, English label, endonym, text direction) |
| `src/lib/i18n/strings.ts` | 43 hand-written keys × 14 translations = 602 reviewed strings (nav, hero, app shell) |
| `src/lib/i18n/filled.json` | **431 strings × 14 locales = 6,034 generated entries** — the bulk of the site |
| `src/components/i18n/LanguageProvider.tsx` | context + persistence + the DOM matcher |
| `src/components/i18n/LanguageSwitcher.tsx` | the globe/select control |
| `scripts/i18n-audit.ts` | `npm run i18n:audit` — coverage % and the ranked list of anything still English |
| `scripts/i18n-fill.ts` | `npm run i18n:fill` — generates gaps via MyMemory / DeepL / OpenAI / LibreTranslate |
| `scripts/i18n-merge.ts` | `npm run i18n:merge` — merges reviewed `scripts/mt/*.txt` batches into `filled.json` |
| `scripts/i18n-verify.ts` | `npm run i18n:verify` — end-to-end browser test in every locale |
| `scripts/i18n-strings.py` | regenerates `strings.ts` from a compact table |

Mounted in `src/app/layout.tsx`, so **every** route is covered — public pages, the login and
registration screens, the legal pages and the signed-in app shell. The switcher sits in
`PublicSite.tsx` (header + mobile chip row), the auth layout (login/register) and
`AppShell.tsx` (sidebar + mobile top bar).

## Locales

English · Deutsch · Français · Italiano · Español · Português · Nederlands · Türkçe ·
Bahasa Indonesia · Русский · العربية (RTL) · 简体中文 · 日本語 · 한국어 · हिन्दी

Choice persists in `localStorage` + a `meridian_locale` cookie (1 year), survives navigation
and reloads, and pages without a visible picker (login, register, legal) follow the stored
preference. `<html lang>` and `dir` are updated, so Arabic flips the layout.

## How the translation happens

`LanguageProvider` builds an index for the active locale, walks the DOM's text nodes and
replaces an exact match with the translation, preserving surrounding whitespace. It also
translates `placeholder`, `aria-label`, `title` and `alt`, skips
`SCRIPT/STYLE/NOSCRIPT/TEXTAREA/CODE/PRE`, any `svg`/`path`, and anything marked
`data-no-translate`. A `MutationObserver` re-applies after client-side navigation or state
changes, so a language switch never leaves stale English behind.

`filled.json` is merged **over** `strings.ts`: the hand-written copy always wins, generated
entries only fill gaps. Nothing calls out to a translation service at runtime — the dictionary
ships with the bundle.

## What is deliberately *not* translated

- **The brand name** `Meridian`.
- **Language endonyms and picker labels** (`Deutsch`, `日本語`, …) — they stay readable in
  their own language.
- **Sample data**: the name `Alex Morgan` and the example address `you@example.com`.
- **Amounts and numeric fragments** (`£8,420`, `.50`, `−£42.80`, `↓ 8%`). The UI splits
  pounds and cents into separate nodes, so re-formatting them per locale would break the
  layout ("8.420 £.50"). They keep the source formatting in every locale — normal for a UK
  bank, and the audit excludes them from the denominator.

Everything else on the page is translated, including the mock dashboard card inside the hero
illustration.

## Regenerating or extending

```bash
npm run dev                       # or: npx next start after a build

npm run i18n:audit                # what is still English? (ranked by frequency)
npm run i18n:fill -- --dry-run    # same list, as a fill plan
npm run i18n:fill -- --provider=mymemory --workers=4     # no API key needed
DEEPL_API_KEY=xxx npm run i18n:fill -- --provider=deepl  # best quality; free tier is plenty
npm run i18n:verify               # browser test: is any English left in any locale?
```

- `i18n:fill` is resumable: it skips strings already in `filled.json`, so a long run can be
  interrupted. It never touches `strings.ts`.
- Reviewed batches live in `scripts/mt/*.txt` (page copy), `scripts/mt2/*.txt` (login,
  register, privacy, terms, cookies, legal) and `scripts/mt3/*.txt` (image alts, aria-labels,
  placeholders, the "or" divider) as `NNN|translation` rows aligned to
  `scripts/i18n-missing*.json`. `npm run i18n:merge` validates the row indexes before writing,
  so a misaligned file fails loudly instead of shifting every translation by one.

### A note on quality

The 602 strings in `strings.ts` are hand-written and reviewed. The 6,034 entries in
`filled.json` are a generated first pass: translated in bulk, then spot-checked and corrected.
German began as a machine pass and was fully retranslated by hand after it produced errors
("Salary" → "Geha t", "bank." → "Bank in Rechnung gestellt werden.").

**Before going live, have the legal pages reviewed.** `privacy`, `terms`, `cookies` and `legal`
are translated for completeness, but legal text in 14 languages needs a human with local
qualification — the English source itself says it is a draft pending review by the operating
entity. Treat the translations as a starting point for that review, not as approved copy.

## Coverage commands and limits

`npm run i18n:audit` audits 20 public routes: `/`, `/about`, `/careers`, `/community`,
`/investment-centres`, `/loans`, `/loans/mortgage`, `/loans/business`, `/loans/car`, `/faq`,
`/help`, `/contact`, `/security`, `/mobile-app`, `/login`, `/register`, `/privacy`, `/terms`,
`/cookies`, `/legal`.

The signed-in area (`/app`, `/app/accounts`, `/app/activity`, `/app/payments`, `/app/cards`,
`/app/payees`, `/app/profile`, `/app/security`, `/app/notifications`) uses the same provider
and the same dictionary, so it translates the moment you are signed in. It needs a live
database and a session to audit, so it is not in the crawl; to include it, start the app with
your `DATABASE_URL`, sign in, and run:

```bash
PAGES="/app,/app/activity,/app/payments,/app/cards,/app/payees,/app/profile" npm run i18n:audit
```

Anything it reports there is a gap of the same kind — add it to `STRINGS` or let `i18n:fill`
generate it.

## Bundle size

`filled.json` is ~510 KB of JSON (~120 KB gzipped) shipped once in the client bundle, because
the provider translates in the browser. That is acceptable for a demo but it is all 15 locales
for every visitor. If you want to trim it, the next step is splitting `filled.json` per locale
and importing only the active one:

```ts
const dictionaries = {
  de: () => import("./filled/de.json"),
  fr: () => import("./filled/fr.json"),
  // …
};
const dict = await dictionaries[locale]();
```

That turns it into one small chunk per language, loaded on demand.
